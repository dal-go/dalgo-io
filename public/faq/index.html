DALgo / DALgo FAQ

DALgo FAQ

DALgo is an open-source database abstraction layer (DAL) for Go and TypeScript: one interface for records, queries and transactions, with adapters for different databases. An ORM (object-relational mapper) maps objects to relational tables; SQL (Structured Query Language) is the query language of relational databases; CRUD means create, read, update and delete, the four basic record operations. Start with DALgo for Go, DALgo for TypeScript, the adapter matrix or the articles.

What is DALgo?

DALgo is a database abstraction layer for Go applications. Its README describes one small, consistent API for records, queries, transactions, hooks and schema-aware key mapping, while the storage backend stays an implementation choice. A TypeScript implementation, @dalgo/core, lives in a separate repository. See DALgo for Go.

Is DALgo an ORM (object-relational mapper)?

DALgo is a database abstraction layer, not a full ORM. GORM describes itself as an ORM for relational databases; DALgo gives the same record calls on SQL and on other stores, such as memory and Firestore. The core module has a small orm package that maps collections and fields onto DALgo collection references and conditions. DALgo vs GORM compares the two.

Which databases does DALgo support?

The core module includes dalgo2memory (in memory) and dalgo2fs (filesystem). The README lists separate adapter modules for SQL engines through dalgo2sql, PostgreSQL, SQLite, MySQL, Microsoft SQL Server, Oracle, Firestore, Datastore, MongoDB, Redis, DynamoDB and more. Each adapter supports different operations; the adapter matrix lists them one by one.

Is DALgo open-source, and under what licence?

Yes. The Go module is dal-go/dalgo under the MIT License. The TypeScript package @dalgo/core is dal-go/dalgo-js, also under the MIT License.

Does DALgo support transactions?

Yes. RunReadonlyTransaction runs a function with read access, and RunReadwriteTransaction runs one that can also write. With typed collections, reads take a read session and writes take a write session, so writes are only reachable inside RunReadwriteTransaction. See Interfaces.

How do I test code without a real database?

Use dalgo2memory, the built-in in-memory adapter: dalgo2memory.NewDB() returns a database that runs the same record, query and transaction code. The README says it can run many structured query features end to end, which makes it a practical default for unit tests. The Quick Start starts with it.

What happens when an adapter does not support a feature?

The adapter returns dal.ErrNotSupported. DALgo does not try to hide every database difference; the error keeps the core API honest. The adapter matrix shows which operations each adapter supports.

How do I install DALgo?

For Go, run go get github.com/dal-go/dalgo, then add the adapter module for your database. For TypeScript, run pnpm add @dalgo/core; the core package does not connect to a database by itself, so you add an adapter too. See the Quick Start.

Is there a TypeScript version of DALgo?

Yes. @dalgo/core is the browser-neutral TypeScript implementation, with hierarchical keys, typed collections, structured queries, records, database sessions and transaction-only writes. Its first adapter is for Firestore and uses Firebase's modular Web SDK in the browser. See DALgo for TypeScript.

Does DALgo work with Firestore?

Yes. In Go, the dalgo2firestore adapter connects DALgo to Cloud Firestore. Firestore in Go: CRUD and transactions with DALgo creates, reads, updates and deletes a document and runs a read-write transaction, and runs the same functions on the in-memory adapter in tests.

When should I not use DALgo?

DALgo earns its place when the same domain code must run against more than one store, including a test double. It is the wrong tool when the engine's own query language is the product. When to use DALgo, and when not to lists the cases.

What is TugQL?

TugQL is a readable YAML format for DALgo structured queries. Its Go implementation is the tugql package in the main module, which serializes dal.StructuredQuery. See TugQL.

Who maintains DALgo?

DALgo is developed in the dal-go GitHub organization by the DALgo contributors; CONTRIBUTING.md explains how to contribute. DALgo provides the data-access seam in DataTug's development ecosystem, and Sneat Go services also depend on the module. See Technology behind DALgo.
