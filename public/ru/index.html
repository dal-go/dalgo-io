Открытый код · Модуль Go · Пакет TypeScript

Один интерфейс. Много баз данных. Без переписывания.

DALgo — слой абстракции баз данных для Go и TypeScript. Пишите логику предметной области один раз, против единого хорошо протестированного интерфейса, — и меняйте Postgres на Firestore, а хранилище в памяти на настоящее, не трогая бизнес-код. Модуль для Go — основная реализация; пакет для TypeScript, @dalgo/core, опубликован в npm.

Начать pkg.go.dev $ go get github.com/dal-go/dalgo $ npm install @dalgo/core
01 — Зачем нужен DAL

Хранилище — деталь, а не судьба.

Шесть причин, по которым разработчики берут DALgo с первого дня. Подробнее — в статье Why use DALgo, а границы применимости — в When to use DALgo, and when not to (обе на английском).

Логика, не зависящая от хранилища

Пишите бизнес-код против dal.DB. Где он будет жить — в Postgres, Firestore или в JSON-файле на диске, — решите позже.

Меньше кода, он читается лучше

Один небольшой API с чёткой позицией заменяет горы шаблонного кода под конкретные драйверы. Записи, ключи, запросы, транзакции — одинаково для каждого адаптера.

Тестируемость по построению

В тестах подставляйте вместо боевого драйвера встроенный адаптер dalgo2memory. Нужны моки? Сгенерированный пакет mocks входит в основной репозиторий.

Хуки и логирование — бесплатно

Поскольку каждая операция проходит через один интерфейс, наблюдаемость и аудит — это обёртка, а не рефакторинг.

Один набор сквозных тестов

Десять адаптеров на Go в CI проходят один и тот же общий набор тестов на соответствие. Соответствие — это контракт; про остальные адаптеры ниже сказано, что они поддерживают, а что нет.

Транзакции в духе Go

Транзакции только для чтения и для чтения и записи — полноправная часть интерфейса. Передайте замыкание — получите атомарность, не пропуская типы транзакций конкретных драйверов в предметный код.

02 — Адаптеры

Один интерфейс. Разные хранилища.

Два адаптера входят в основной модуль. Десять адаптеров на Go проходят общий набор тестов на соответствие; остальные перечислены ниже вместе с их ограничениями.

  • Ядро

    dalgo

    Сам интерфейс. dal, orm, record, update, транзакции, ошибки.

    github.com/dal-go/dalgo
  • Встроенный · В памяти

    dalgo2memory

    Адаптер в памяти из основного модуля — хранилище по умолчанию для тестов, примеров и локальной разработки. Выполняет большинство возможностей структурированных запросов целиком.

    github.com/dal-go/dalgo/adapters/dalgo2memory
  • Встроенный · Файловая система

    dalgo2fs

    Встроенный адаптер, отображающий файловую систему ОС на записи DALgo, — удобен для демо и простого локального хранения.

    github.com/dal-go/dalgo/adapters/dalgo2fs
  • SQL

    dalgo2sql

    Адаптер для стандартного database/sql — любой совместимый драйвер.

    github.com/dal-go/dalgo2sql
  • SQL

    dalgo2sqlite

    Драйвер для SQLite: схема, DDL и операции с учётом параллелизма поверх dalgo2sql.

    github.com/dal-go/dalgo2sqlite
  • SQL

    dalgo2postgres

    Драйвер для PostgreSQL поверх dalgo2sql: принудительно включает диалект postgres, читает каталоги и применяет DDL Postgres.

    github.com/dal-go/dalgo2postgres
  • SQL

    dalgo2mysql

    Драйвер для MySQL поверх dalgo2sql: чтение схемы и DDL MySQL. В CI набор тестов на соответствие запускается на MySQL 8.

    github.com/dal-go/dalgo2mysql
  • С историей · inGitDB

    dalgo2ingitdb

    Адаптер для inGitDB — базы данных на основе Git, с ветвящимися и сливаемыми данными. Чтение и запись; транзакция — это коммит Git. Живёт в организации inGitDB.

    github.com/ingitdb/dalgo2ingitdb
  • Документная · HTTP API

    dalgo2openvaultdb

    Адаптер для OpenVaultDB через её HTTP API ovdb serve: чтение и транзакционная запись.

    github.com/dal-go/dalgo2openvaultdb
  • NoSQL · Облако

    dalgo2firestore

    Для Google Cloud Firestore — глобально распределённой документной NoSQL-базы.

    github.com/dal-go/dalgo2firestore
  • Веб · Только чтение

    dalgo2http

    Декларативные HTTP-эндпоинты — JSON, а также именованные ресурсы XML и CSV — как коллекции DALgo. По замыслу только чтение.

    github.com/dal-go/dalgo2http

Тоже доступны: только чтение или частичная поддержка

У этих адаптеров на Go есть собственные тесты, но общий набор тестов на соответствие они не проходят. Большинство работают только на чтение или по замыслу покрывают лишь часть интерфейса.

  • dalgo2files — файлы JSON, только чтение
  • dalgo2logs — файлы журналов, только чтение
  • dalgo2mssql — SQL Server, компилятора структурированных запросов пока нет
  • dalgo2oracle — Oracle, компилятора структурированных запросов пока нет
  • dalgo2duckdb — DuckDB, чтения схемы и DDL пока нет
  • dalgo2libsql — libSQL / Turso, только чтение
  • dalgo2postgrest — PostgREST, только чтение
  • dalgo2mongodb — MongoDB, только чтение
  • dalgo2couchdb — CouchDB, только чтение
  • dalgo2redis — Redis, только команды чтения
  • dalgo2typesense — Typesense, только чтение
  • dalgo2bigquery — BigQuery, только чтение
  • dalgo2d1 — Cloudflare D1, только чтение
  • dalgo2namecheap — домены и DNS Namecheap, чтение и запись

Сопутствующие модули

  • dalgo/mocks — сгенерированные моки для всех интерфейсов DALgo, теперь часть основного репозитория (отдельный репозиторий mocks4dalgo архивирован).
  • dalgo/dalgotest — общий набор тестов на соответствие (dalgotest.RunConformance), который проходят адаптеры выше; теперь часть основного репозитория (отдельный репозиторий dalgo-end2end-tests архивирован).
  • dalgo-demo — посмотрите, как мало кода нужно для работающего приложения.
  • dalgo4auth — готовые структуры записей для таблиц аутентификации пользователей.
  • dalgo-memcache-appengine — обёртка над memcache App Engine для транзакций DALgo.
03 — Быстрый старт

Установите ядро. Выберите адаптер. Запишите данные.

Рабочий пример короче 40 строк.

  1. 1

    Установите основной модуль. Встроенный адаптер dalgo2memory идёт вместе с ним — дополнительных зависимостей для старта не нужно.

  2. 2

    Откройте базу данных. Возвращённый dal.DB — единственный тип, о котором должно знать ваше приложение.

  3. 3

    Опишите запись, задайте её данные и прочитайте обратно по ключу.

  4. 4

    Позже замените dalgo2memory на dalgo2sqlite или dalgo2firestore. Ваши обработчики не меняются.

main.go Go 
// $ go get github.com/dal-go/dalgo

package main

import (
    "context"
    "fmt"

    "github.com/dal-go/dalgo/dal"
    "github.com/dal-go/dalgo/adapters/dalgo2memory"
)

type User struct {
    Name  string `json:"name"`
    Email string `json:"email"`
}

func main() {
    ctx := context.Background()
    db := dalgo2memory.NewDB()

    key := dal.NewKeyWithID("users", "u1")
    user := &User{Name: "Ada Lovelace", Email: "ada@example.com"}
    if err := db.Set(ctx, dal.NewRecordWithData(key, user)); err != nil {
        panic(err)
    }

    var got User
    record := dal.NewRecordWithData(key, &got)
    if err := db.Get(ctx, record); err != nil {
        panic(err)
    }
    if record.Exists() {
        fmt.Println(got.Email)
    }
}
04 — TypeScript

Та же идея на TypeScript.

@dalgo/core — реализация DALgo на TypeScript, не привязанная к браузеру: иерархические ключи, типизированные коллекции, структурированные запросы и запись только внутри транзакций.

Установите пакет из npm: npm install @dalgo/core. У пакета нет собственного SDK базы данных, и сам он к базе не подключается — это делает адаптер. Исходный код: dal-go/dalgo-js.

Адаптеры для TypeScript лежат в dal-go/dalgo-http-adapters. Семь из них опубликованы в npm. Чтение и запись: @dalgo/firestore (эталонный адаптер), @dalgo/indexeddb и @dalgo/sqlite-wasm. Только чтение или только запросы: @dalgo/ovdb, @dalgo/bigquery, @dalgo/d1 и @dalgo/http. Остальные в разработке и пока не в npm.

Зрелость: @dalgo/core пока в версиях 0.x, а несколько адаптеров работают только на чтение или только на запросы. В README каждого адаптера указано, что он поддерживает; операция, которую он не умеет, завершается явной ошибкой.
query.ts TypeScript 
// $ npm install @dalgo/core
import { collection, key } from "@dalgo/core";

interface Item {
  title: string;
  done: boolean;
  rank: number;
}

const spaceKey = key("spaces", spaceId);
const items = collection<Item>("items").in(spaceKey);

const query = items.query()
  .where("done", "==", false)
  .orderBy("rank")
  .limit(25)
  .build();

// Pass query to an adapter updated for @dalgo/core.
05 — Типизированные коллекции

Меньше церемоний для повседневного CRUD.

Обобщённый dal.Collection[T] без сессии возвращает типизированные значения напрямую: без возни с ключами, без обёрток записей, без приведения типов. Это надстройка над основным API, и она работает с любым адаптером для Go.

collections.go Go 
type User struct {
    Name  string `json:"name"`
    Email string `json:"email"`
}

// CollectionName (value receiver) names the collection.
func (User) CollectionName() string { return "users" }

// A Collection[T] holds no session — declare it once and reuse it.
var Users = dal.CollectionOf[User]()

func demo(ctx context.Context, db dal.DB) error {
    // Writes take a WriteSession — only reachable inside a transaction.
    if err := db.RunReadwriteTransaction(ctx,
        func(ctx context.Context, tx dal.ReadwriteTransaction) error {
            return Users.Set(ctx, tx, "u1",
                User{Name: "Ada Lovelace", Email: "ada@example.com"})
        }); err != nil {
        return err
    }

    // Reads take a ReadSession (a plain dal.DB works) and return T.
    user, err := Users.Get(ctx, db, "u1")
    if err != nil { // not-found via dal.IsNotFound(err)
        return err
    }
    fmt.Println(user.Email)
    return nil
}

Тот же объект умеет и Insert (с генерацией id), InsertWithID, All, First, Count, Exists, Update, Delete, пакетный InsertMany и In(parentKey) для вложенных коллекций.

Стандартный database/sql и DALgo

Одни и те же операции, написанные на стандартной библиотеке и на DALgo. Версия на DALgo не зависит от бэкенда: тот же код работает с Firestore, SQL, файловой системой и адаптером в памяти.

Прочитать пользователя по id — и сразу вернуть типизированное значение.

database/sql Go 
// Standard library: hand-written SQL + Scan.
type User struct {
    ID    int
    Name  string
    Email string
}

func GetUser(ctx context.Context, db *sql.DB, id int) (*User, error) {
    row := db.QueryRowContext(ctx,
        "SELECT id, name, email FROM users WHERE id = ?", id)

    u := &User{}
    err := row.Scan(
        &u.ID,
        &u.Name,
        &u.Email,
    )
    if errors.Is(err, sql.ErrNoRows) {
        return nil, nil
    }
    if err != nil {
        return nil, err
    }
    return u, nil
}
DALgo Go 
// DALgo: one typed call, any backend.
type User struct {
    ID    int
    Name  string
    Email string
}

func GetUser(ctx context.Context, db dal.DB, id int) (User, error) {
    return dal.CollectionAt[User]("users").Get(ctx, db, id)
}

В одной транзакции: загрузить пользователя; если он не заблокирован — пометить его и добавить запись Ban.

database/sql Go 
// Standard library: manual BEGIN / COMMIT / ROLLBACK.
type User struct {
    ID       int
    Name     string
    Email    string
    IsBanned bool
}

type Ban struct {
    UserID       int
    BanTimestamp time.Time
}

func BanUser(ctx context.Context, db *sql.DB, id int) error {
    tx, err := db.BeginTx(ctx, nil)
    if err != nil {
        return err
    }
    defer tx.Rollback()

    var u User
    err = tx.QueryRowContext(ctx,
        "SELECT id, name, email, is_banned FROM users WHERE id = ?", id).
        Scan(&u.ID, &u.Name, &u.Email, &u.IsBanned)
    if err != nil {
        return err
    }
    if u.IsBanned {
        return nil
    }

    if _, err = tx.ExecContext(ctx,
        "UPDATE users SET is_banned = TRUE WHERE id = ?", id); err != nil {
        return err
    }
    if _, err = tx.ExecContext(ctx,
        "INSERT INTO bans (user_id, ban_timestamp) VALUES (?, ?)",
        id, time.Now()); err != nil {
        return err
    }
    return tx.Commit()
}
DALgo Go 
// DALgo: one closure, the driver runs the transaction.
type User struct {
    ID       int
    Name     string
    Email    string
    IsBanned bool
}

type Ban struct {
    UserID       int
    BanTimestamp time.Time
}

func BanUser(ctx context.Context, db dal.DB, id int) error {
    return db.RunReadwriteTransaction(ctx,
        func(ctx context.Context, tx dal.ReadwriteTransaction) error {
            users := dal.CollectionAt[User]("users")
            user, err := users.Get(ctx, tx, id)
            if err != nil {
                return err
            }
            if user.IsBanned {
                return nil
            }
            if err = users.Update(ctx, tx, id,
                []update.Update{update.ByFieldName("IsBanned", true)}); err != nil {
                return err
            }
            bans := dal.CollectionAt[Ban]("bans")
            _, err = bans.Insert(ctx, tx, Ban{UserID: id, BanTimestamp: time.Now()})
            return err
        })
}
06 — Интерфейс

Достаточно мал, чтобы запомнить.

Достаточно строг, чтобы держать все адаптеры в рамках.

Каждый адаптер DALgo — SQL, NoSQL, встраиваемый, файловый — реализует один и тот же контракт dal.DB. Операции чтения живут в ReadSession, операции изменения — в ReadwriteSession. Транзакции — это замыкания: вы передаёте функцию, драйвер даёт вам сессию, а ваш код никогда не видит дескриптор конкретного драйвера.

Драйверы, которые не могут выполнить операцию, возвращают dal.ErrNotSupported — явный отказ лучше молчаливой чепухи.
dal/db_database.go Go 
package dal

type DB interface {
    ID() string
    Adapter() Adapter
    Schema() Schema
    TransactionCoordinator
    ReadSession
    ConcurrencyAware
}

type TransactionCoordinator interface {
    RunReadonlyTransaction(ctx context.Context,
        f ROTxWorker, opts ...TransactionOption) error

    RunReadwriteTransaction(ctx context.Context,
        f RWTxWorker, opts ...TransactionOption) error
}

type ReadSession interface {
    Get(ctx context.Context, record Record) error
    GetMulti(ctx context.Context, records []Record) error
    ExecuteQueryToRecordsReader(ctx context.Context,
        query Query) (RecordsReader, error)
}

type ReadwriteSession interface {
    ReadSession
    Insert(ctx context.Context, r Record, opts ...InsertOption) error
    Set(ctx context.Context, r Record) error
    Update(ctx context.Context, key *Key,
        updates []update.Update, pre ...Precondition) error
    Delete(ctx context.Context, key *Key) error
}
07 — Запросы и схема

Больше, чем get и set.

Построитель структурированных запросов, иерархические коллекции и ключи с учётом схемы — с поддержкой по возможностям адаптера.

DALgo включает построитель структурированных запросов для типичных чтений: фильтры, сортировка, LIMIT, выбор столбцов, GROUP BY / HAVING, агрегаты вроде COUNT(*) и SUM, а также внутренние и левые соединения по равенству. Ключи могут описывать вложенные пути документов, например countries/ireland/cities/dublin, а родительский ключ ограничивает запрос вложенной коллекцией.

Поддержка зависит от возможностей адаптера: бэкенд, который не умеет выполнять часть запроса, возвращает dal.ErrNotSupported, поэтому тесты используют одну форму запроса и корректно пропускают недоступное. Сериализованный формат запросов описан в TugQL (на английском).
query.go Go 
// Query the largest cities, projecting two columns.
cities := dal.NewRootCollectionRef("cities", "")

q := dal.From(cities).NewQuery().
    WhereField("Country", dal.Equal, "IE").
    OrderBy(dal.DescendingField("Population")).
    Limit(10).
    SelectColumns(
        dal.Column{Expression: dal.Field("Name")},
        dal.Column{Expression: dal.Field("Population")},
    )

records, err := dal.ExecuteQueryAndReadAllToRecords(ctx, q, db)

Используется в разработке DataTug

DataTug помогает разработчикам изучать схемы баз данных, писать и запускать запросы и понимать их результаты. DALgo служит швом доступа к данным в среде разработки DataTug. Прочитайте, как создавались инструменты разработки DataTug (на английском).
